# 人生において唯一不変なことは変化である。

## ソフトウェア設計で考慮すべき４つの変化のベクトル（事業活動・組織の構造・業務知識・システムの成長）

- 価値を生み出すソフトウェア設計には業務知識が不可欠である
- ソフトウェア開発で最も難しいことは業務知識の習得（特に、中核の業務領域を理解することは大きな挑戦となる）


- １：区切られた文脈の境界は業務知識の深さに合わせるのが良いらしい
- ２：システムの成長はソフトウェアが健全である証、機能の追加が続くのは、システムがうまくいっている証拠
- １と２を満たしているシステムはユーザーに価値を提供し、更なる要求に応え、競合プロダクトと対抗できている状態になっている。

- ソフトウェア成長における問題点：
  -  大きな泥団子になる可能性＝機能拡張の際に設計を再検討せずに無秩序に成長してしまった状態
  - 成長することでコンポーネントの境界が膨張し、ますますそこに機能が追加される。

## ドメイン駆動設計の主要な関心事は、「境界」をどう設定するかである。
- 自魚活動を構成する要素（業務領域）、モデル（区切られた文章）、不溶性（値オブジェクト）、一貫性（集約）、それぞれの教会の設定
- **過去の設計判断に起因する複雑さを特定し取り除くこことが重要**

### ドメイン駆動設計の基本的な進め方
- 1.事業活動と業務領域を分析する
- 2.対象とする業務領域のモデルを作る
- 3.モデルに基づいてソフトウェアを設計し実装する
