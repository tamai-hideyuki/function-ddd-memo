## ドメイン駆動設計の考え方とやり方を取り入れていくための戦略的なやり方

- **まず最初にすることは２つだけ**
  - 事業活動を理解する
  - システムの構造がどうなっているかを理解する

# ソフトウェアの「設計」判断を「事業活動（ドメイン）」で駆動するのがドメイン駆動設計（集約や値オブジェクトの実装がどっメイン駆動設計ではない）

- 同じ言葉を使うことがドメイン駆動設計に取り組む土台
- 同じ言葉：業務知識を発見し、お互いの意図を伝え、役に立つモデルを作るために絶対に必要

- なんでもできるは実際にはなんの役にも立たないことと同義
- 異なるモデルが混在すると、認知の負荷が大きくなり、ソフトウェアが不必要に複雑になる


# DDDのはじめかた：下記の問いを元に必要な道具を選定して段階的に始めると良い👍
- 自社の事業目標は何？
- 目標を達成するための事業方針はどうなってる？
- 事業活動がどのような事業領域に分かれていますか？それぞれの事業領域のカテゴリーがなんでしょうか？
- 事業価値を生み出す源泉はどこにあるでしょう？
